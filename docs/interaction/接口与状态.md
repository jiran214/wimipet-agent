# C 模块接口草案 c-lab/0.1

这是 C 模块内部独立实现与可联调提案，**尚未与 A / B / D 或装配层协商，不声称跨模块兼容**。未引入其他业务模块依赖。核心入口为 `modules/interaction/src/engine.py` 的 `Interaction`；生产装配可直接实例化核心并注入依赖，无需启动调试 HTTP 服务。

## 依赖与生命周期

`Interaction(roles, model, capture, clock, timeout=8)`：实例拥有唯一消息 List、调度任务、轮次策略、动作请求和观察策略。所有方法在同一个 asyncio 事件循环调用；HTTP 演示通过线程安全队列提交，业务状态没有第二份存储。`clock()` 返回单调秒数，测试使用可控时钟；模型 I/O 超时使用事件循环的实际时间。

角色快照：`{id, name, persona, actions: string[]}`。不修改角色源配置。构造时复制；演示人设修改只作用于会话快照。角色包读取和版本协商待与 B 联调。

模型接口：`async generate(role, context) -> {text?: string, action?: string|null}`，允许两字段都空而保持安静。模型只收到快照和筛选后的消息；不能访问会话状态。未知动作不输出为请求，任务记录 `action_error=unknown-action`。每个角色独立任务，失败不影响其他角色。模型实现应配合取消；核心设置硬截止并丢弃超时结果，不能强杀任意第三方后台任务。

画面接口：`async capture(scope, scene) -> {description, image}`。范围为 `active-window|desktop`，场景为递增整数；调用方闭包关联场景和请求任务 ID。演示图片是 fixture 文件名或用户显式上传的 data URI；**正式图像引用、采集时间戳、来源 ID、排除区域和保留策略待与 A 协商**。不得将本地调试图片表示方式当成正式角色包/画面协议。

`await close()` 取消并等待所跟踪任务；`await reset()` 取消任务并清空体验状态，不执行文件删除。传入依赖应自行释放其底层资源。标准库真实适配器的线程取消限制见运行说明。

## 输入与输出

| 方法 | 语义 |
| --- | --- |
| `submit(text, targets=None, kind='text', image=None)` | 立即追加用户/导演输入，停止旧轮次，再并发调度目标集合。kind 是 text / image / story。targets 为角色 ID 集合，None 为公开；空集合无效。 |
| `start_auto(rounds=3)` | 停止旧任务，最多 1–12 轮，按当前角色集合轮换。每轮使用已发布公共上下文；不因输出或反馈自启动。 |
| `cancel()` | 推进世代并取消在途任务，后续输入仍可继续使用同一会话。 |
| `desktop(source='window', force=False)` | 更新场景；过滤自身输出，按冷却请求画面。force 仅绕过冷却，不绕过暂停。返回是否调度采集。 |
| `observation(paused, scope, cooldown)` | 更新观察配置并使在途画面及视觉模型失效。cooldown 为 0–300 秒的本地实现参数，非已协商产品阈值。 |
| `feedback(action_id, status)` | 状态为 accepted / rejected / completed；完成前必须接受，拒绝和完成为终态。所属角色可见，不触发模型或采集。 |
| `remove(role_id)` | 移除参与者；在途结果不再发布。保留会话中的既有消息，恢复样例可重建角色。 |
| `viewer(role_id)` | 正式角色可见消息投影，只包含公共或明确接收范围内的消息，无调试上下文。 |
| `snapshot(debug=False)` | 用户/管理员视图，包含所有消息（含私聊）、动作和任务。绝不可直接分发给其他角色。debug=True 增加实际模型输入、输入事件和演示操作步骤。 |

消息为 `{id, seq, sender, text, audience, kind, time, image?}`。`seq` 是当前会话内递增顺序；`audience` 是 `all` 或角色 ID 数组，时间是单调时钟调试值。消息没有按角色重复存储，导出的投影和模型上下文是只读副本，不是第二份权威记录。

生成上下文还按**输出范围**筛选：私聊可使用目标角色可见且本轮全部接收者都有权查看的历史；公开发言只使用公共历史，防止私聊通过公开引用泄漏。导演事件使用相同范围机制，模拟角色是否“知道导演身份”的产品编辑语义待定；当前保留 sender=director，不自动虚构幕后信息。

动作：`{id, role, action, status, job}`。初始 status=requested，绝不代表接受或完成。状态反馈写入同一个消息 List，以私有 action-feedback 事件仅提供给所属角色。物理执行与身体限制均由外部依赖承担。

任务：`{id, role, status, source_seq? | scene?, scope?, error?, action_error?}`；状态有 running / done / silent / failed / timeout / cancelled / stale。可关联角色、输入序号或观察场景；动作关联 job。版本字符串附在快照，不暴露 Python 对象或平台句柄。

## 本地 HTTP 调试桥

GET `/api/state` 返回管理员调试快照，其他 `/api/*` 仅接受 JSON POST。命令路径与前端一一对应：send、auto、stop、reset、observe、window、observation、feedback、role、remove、view。无认证，仅为回环单用户调试，禁止复用于远程产品服务。输入图片仅接受内置文件名或 2MB 内 PNG/JPEG data URI；入口检查媒体头，不进行文件内容解码安全承诺。

正式输出订阅、错误码稳定性、动作 schema、角色快照版本、图像句柄和消息 DTO 尚待跨模块联调。D 应消费 C 提供的消息投影而不是自建另一份对话，A 应通过动作 ID 回传执行结果；这些是本模块的建议衔接方式，不表示对方已采纳。
