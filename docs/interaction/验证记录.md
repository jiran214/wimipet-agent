机制覆盖：

- 共同样例副本与根共同文件字节一致；同包三个 instanceId 独立，人设 20000/正文 4000 Unicode 码点，图片无正文与附件类型/数量/大小拒绝。
- 正式 Message 的 speaker、audience、attachments、epoch atMs、seq；获准用户/角色视图，异步订阅、先订阅再快照、退订、只读副本、私聊后公开输入过滤；导演事件延续。
- requestId 重复/处理中重复、内容冲突、有效记录容量、单调截止（含墙上时钟回拨）、取消、超时、忽略取消的迟到模型、单角色失败与同伴继续；自动交流有限、插话与移除角色。
- requested/queued/accepted/completed/rejected/interrupted/failed 完整路径，终态不得复活、循环动作不得自行完成、关联错误、重复/冲突事件、无效反馈不能部分提交、传输失败不能伪造身体事实。
- 策略确认 pending/失败/版本不符；暂停恢复后的旧 revision 画面及模型丢弃；受控时钟冷却、自身事件过滤、CaptureResult 结构化 unavailable 不分析画面；观察取消。
- reset 新 sessionId 隔离旧模型、截图、动作反馈和资源引用；事件 sourceInstanceId 保留、sourceSeq 跨会话单调；close/退订、资源释放失败显式报告并在关闭重试。
- 真实模型适配器使用假传输验证 resolver 图片编码、配置缺失、凭据不进入请求正文；未访问真实提供方。

`demo/host_example.py` 直接通过 `src/public.py` 创建核心，消费共同包的模拟 CharacterLoaded，注册同包两个实例，提交图片无正文，重复请求取得相同回执，经 subscribe/getView 获得三条消息。实际关闭报告 `pendingTasks=0`、`providerWorkers=0`、`resourceErrors=[]`、`resourceCleanupPending=[]`。这只是 C 的宿主/假依赖例子，**不是 A/B/C/D 真实消费者集成**。

本轮补充 provider 测试时曾漏导入 ProtocolError，导致一项 NameError；已修正，最终 37 项均通过，没有将那轮失败计为通过。测试等待任务状态、事件与排空，不使用毫秒级固定 sleep 猜测完成。
