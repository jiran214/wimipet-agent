## 4. 已复现的装配问题

### P1：角色包并非可直接消费的共同交付物（B ↔ A/C）

- B 输出 `character-studio/0.1` 单 JSON，资源是嵌入 PNG；A 要求 `A-display/1` 清单及本地帧文件。将 B 的固定包直接交给 `Package.load`，报缺少 schema。
- B 接受最高 2048×2048、16–10000ms 可带小数；A 只接受最高 512×512、10–10000ms 整数。包在 B 合法不代表 A 可以播放。
- B 接触点为动作级归一化坐标，可没有点；A 要求每帧像素接触点及 contactKind、允许状态、优先级，并强制全状态循环 idle。B 不提供全部身体语义，不能通过字段改名无损修复。
- C 读取角色快照和动作 ID 集合，没有 B 角色包加载流程；B 支持较长人设，C 调试编辑入口只接受 2000 字。需明确核心输入与调试界面的能力差别。
- 建议：由 B 主责角色包交换契约，A 给出可播放能力声明；用同一确认包做生产者导出/消费者加载验收。允许降级或拒绝，不能静默捏造悬挂等能力。

### P1：动作生命周期不完整（A ↔ C）

- A 输出 accepted、queued、completed、rejected、interrupted、failed；C.feedback 仅接受 accepted、rejected、completed。
- 探针向 C 提交 queued / interrupted / failed，全部报“未知动作反馈”。真实拖拽中断或渲染失败后，不能维持正确对话事实。
- C 自带 nod/look 动作在 A 的 moss 样例中不存在；直接传送得到未知动作拒绝。此结果不说明 A 校验错误，说明双方不能各自维护能力表。
- 建议：C 补齐终态和转换，A/C 统一请求关联和结果语义；可用动作从实际加载的包及执行器能力推导，不能将 failed 简单转换为 completed，或用静态假成功掩盖缺口。

### P1：用户输入边界不一致（D ↔ C）

- D 允许图片无正文、最多四图、PNG/JPEG/WebP/GIF、每图 5MB、正文最长 8000 字；C.submit 必须有 1–4000 字正文，单 image 字段；C 调试 HTTP 只接收 2MB 内 PNG/JPEG。
- 探针执行 C.submit('', kind='image', image='share.png')，实际拒绝。
- 建议：C 与 D 对齐用户输入契约和能力提示；明确多图是否支持、格式转换由谁负责。图像是独立输入意图，不应临时填一条假用户正文来绕过校验。调试 HTTP 限制不能未经检查直接当成生产接口。

### P1：消息和气泡缺少宿主适配（C ↔ D）

- C 输出 sender/time（单调秒）/image；D 要求 speakerId/at（epoch 毫秒）/attachments，以及 sessionId、角色位置、获准消息视图和订阅。
- 原样把 C 消息传给 D.layoutBubbles，气泡为 0；显式映射发言者与时间后，三个角色消息得到 3 个气泡。这只证明布局输入可以转换，不证明 DOM/原生窗口装配完成。
- C.snapshot 是用户/管理员视图，包含所有私聊；不能未经用户视图策略选择就当成任意角色可见流。D 演示消息源不能保留为第二个正式对话源。
- C 暂无正式变化订阅，D 需要 subscribe；可先由宿主做只读轮询桥，但要规定时序、断开和释放，并标明不是新权威存储。

### P1：运行宿主和坐标尚未设计（A ↔ D ↔ 装配）

- A 为 Python/Tk/Win32，C 为 Python asyncio，B/D 为 Node/浏览器。语言差异可通过 IPC/本地服务连接，但线程、进程、生命周期和宿主没有落地方案。
- A 用虚拟桌面物理像素及单调场景毫秒；D 用舞台 CSS 像素和 epoch 毫秒。直接传位置和时间会导致气泡错位或立即过期。
- 浏览器中打开 D 并不会自动得到覆盖全桌面的透明气泡。需要明确原生 UI 宿主、焦点、穿透、DPI/坐标换算和关闭顺序。
- A 当前隐藏自身窗口以排除截图，没有接入 D 跨进程窗口排除。正式采集前需解决自身输出反复进入模型的问题。

### P2：观察与运行体验的剩余风险

- A 当前 Tk 宿主同步截图，慢采集可能阻塞即时身体响应；这是源码/原文已披露限制，本次未作延迟压力测试。
- C 的 asyncio 单线程使用约定需由宿主遵守，不能从 Tk 主线程直接调用；真实 HTTP 模型在线程中运行，任务取消不等同于提供方停止计算。
- 角色包身份、运行实例身份、会话身份应分别定义。A 可从同一包创建多个实例，C 以角色 id 为字典键；装配若直接用包 id 创建多个实例，会丢失角色区分。

## 5. 实际最小组合探针

脚本：[probe.py](probe.py)，实际结果：[probe-results.json](probe-results.json)。只读取指定 worktree，通过临时目录转换样例包，不修改模块或用户资产。

```powershell
python docs/reviews/first-development/probe.py --a C:/Users/jiran/.codex/worktrees/364c/wimipet-agent --b C:/Users/jiran/.codex/worktrees/a8f1/wimipet-agent --c C:/Users/jiran/.codex/worktrees/65a9/wimipet-agent --d C:/Users/jiran/.codex/worktrees/2f6b/wimipet-agent --output docs/reviews/first-development/probe-results.json
```

除上述失败复现外，探针取得三项正向结果：

1. B 固定包解码至临时 PNG，显式转换为 A 清单后，A 核心可加载并推进。转换假定 feet-only 和全状态，仅为样例可行性证明，不是合格生产适配。
2. C 输出请求经 role/request ID 映射后，A 在 standing 状态播放 wave 并输出 completed，C 正确记录完成；不支持的 nod/look 则保持 rejected。
3. C 文本消息映射 speakerId 与时间后，D 气泡布局能够消费。尚未串起附件、设置、原生位置与实时订阅。

探针不是独立体验台，更不是成品装配层；不覆盖可见 UI、真实模型或全部协议。随机请求 ID 与事件先后可能变化，比较状态和语义，不比较逐字 JSON。

## 6. 开发过程暴露的经验

| 可见过程中的问题 | 已采取的修正/当前状态 | 后续规避措施 |
| --- | --- | --- |
| A 无法通过电脑使用工具激活体验窗口，返回全屏应用画面 | 停止输入，改做程序化 GUI/隐藏窗口检查，保留观感未验收 | 提前安排普通桌面人工体验窗口；机制检查与视觉验收分开 |
| B 播放刷新覆盖帧时长编辑 | 编辑时暂停播放 | 涉及持续刷新和输入的表单先做真实操作测试 |
| B 只检查图片头不够；取消重试有迟到风险 | 增加 PNG CRC 和候选响应保护 | 资产校验与任务世代隔离前置到公共流程 |
| C 毫秒级固定 sleep 测试在 Windows 不稳定 | 改为等待明确任务状态和排空 | 使用可控时钟与状态等待，避免以睡眠猜测完成 |
| C 私聊可能污染后续公开发言 | 按输出接收范围二次筛选上下文 | 验收必须覆盖私聊后公开接话，而不只检查首次私聊 |
| C/D 重复启动或旧服务引发端口/旧页面混淆 | C 增加独占绑定，开发时清理进程；D 明确报端口占用 | 每实例显示版本/模式/端口；自动化用临时端口，仅清理自身进程 |
| D 回调刷新重置接收对象，重置残留图片引用 | 修正选择保持、原子重置与资源释放 | 用可观察回调验证真实接收对象，不能只看页面文字 |
| D 路径重复拼接、历史浏览器错误与定位器歧义 | 开发中修正路径、重新验证 | 命令显式 workdir；浏览器用干净场景/稳定标识并等待本轮状态 |
| 四模块自行定义候选契约并全部留待联调 | 当前已诚实标注，但没有形成共同接口 | 开发首个检查点先交最小协议和共同样例，由消费方验证后再扩功能 |
| 所有对话都禁止触碰装配层 | 范围隔离成功，但无人实施早期组合 | 指定装配负责人，模块负责人维护契约；接口可用就检查一条真实链路 |

这些问题既有已修正的开发故障，也有仍开放的集成缺口；不因最终测试全绿就将两者混为“已经解决”。

## 7. 下一轮优先行动（建议，未实施）

1. 先确定角色包/动作能力、输入输出消息、动作生命周期三组最小交换契约。字段、时间、坐标、身份、限制、错误和取消都需要消费方确认；不用新增业务模块。
2. A/B/C/D 各自创建聚焦的后续需求并关联本报告：A 加载/身体能力，B 交付包，C 输入与状态反馈，D 宿主消息映射和能力提示。保持独立编号，不把修复塞进装配业务逻辑。
3. 指定装配宿主与进程方案，在装配层只做传输、映射、配置和生命周期，模块缺能力则回模块修复。
4. 用同一包先贯通 B→A，再贯通 C→D 文本及 C→A→C 动作；随后加图片、设置暂停、位置和截图。每条链路都要有正向、拒绝、取消与退出场景。
5. 安排用户人工体验 A 的普通桌面观感、B 的制作便捷性、C 的真实模型交流、D 的干扰与阅读体验；独立体验和组合体验分别记录。
6. 技术债分级处理：优先阻断接口与虚假成功风险，再补原生宿主和实际模型证据，之后才扩展动作、故事和视觉精细度。

建议验收门槛从“模块测试通过”提升为“模块独立可体验 + 一个真实消费者用共同样例通过”。现阶段不需要推倒四模块划分；需要补的是模块之间少量、稳定、可验证的约定。
