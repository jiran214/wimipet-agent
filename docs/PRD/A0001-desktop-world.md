## 1. 背景与目标

产品是以陪伴为核心的多角色 Meta 桌面 AI 世界。角色可以理解用户当前内容、与用户及彼此交流并产生故事。A 模块负责让这些角色拥有可信的桌面身体和空间基础：窗口、图标及任务栏既是系统元素，也是角色可以观察和活动的环境。

目标是让多个角色连续显示、自然响应拖拽和窗口变化、播放自定义动作，同时不干扰用户正常工作。身体反馈不等待模型，即使 AI 暂不可用，基础桌面交互也应继续工作。

本模块不决定角色是否知道自己是 AI，也不固定性格或第四面墙台词；这些由用户人设和互动模块决定。当前不考虑商业化，不限定为两只角色，也不将单屏 Windows 等讨论建议视为已确认范围。

## 2. 职责与边界

| 负责 | 不负责 |
| --- | --- |
| 系统桌面结构、系统事件和受控画面采集 | 视觉语义理解、观察时机策略、聊天和故事生成 |
| 多角色渲染、序列帧播放、身体状态与接触关系 | 角色形象生成、动作制作、人设源配置 |
| 拖拽、下落、依附、遮挡、鼠标穿透与动作执行规则 | 气泡内容、聊天面板和界面排版 |
| 输出位置、交互事件和真实执行结果 | 修改用户文件或代用户操作其他软件 |

A 不导入其他业务模块实现，也不要求它们运行。装配层注入接口并负责连接。只读角色包是制作模块的交付物，不共享可变创作状态。

## 3. 需求

### A0001-R01 多角色载入与生命周期

- 从已校验角色包读取身份标识、显示资产及动作描述；不修改包源文件。
- 按角色集合管理载入、显示、移除和资源释放，不硬编码双角色逻辑。
- 角色包采用显式版本加载；热更新方式、数量上限和持久化策略待定。
- 资产缺失或格式不支持应给出明确错误，不让一个角色失败阻塞所有角色。

### A0001-R02 系统感知

- 提供窗口位置、大小、切换、移动、缩放、最小化等结构与变化信息，以及任务栏和桌面图标相关能力。
- 原生平台不支持的能力应可识别，不伪造已获取结果。具体平台支持矩阵后续确定。
- 系统事件与视觉采集分离，不能每次窗口变化都强制截图或请求模型。
- 输出对象标识、来源和采集时刻，使调用方能识别过期状态及系统自身输出。

### A0001-R03 受控画面采集

- 根据外部传入的范围、暂停和排除约束采集画面，返回结果或明确错误。
- 暂停观察后不得继续发起被暂停范围内的采集；在途请求结果须可识别，由上层丢弃或处理。
- 需要支持解决桌宠和气泡被自身再次观察而引发循环的问题；具体排除方案待平台验证。
- 截图是否保存、保留多久尚未确定，不将默认持久保存写为既定需求。
- 截图只负责提供画面，不执行内容理解；看见图标不授予打开、移动或修改文件的权限。

### A0001-R04 身体与桌面互动

- 支持用户拖动角色，以及角色趴在窗口上、贴住或挂住窗口、站在任务栏等目标体验。
- 窗口移动时同步更新依附关系与位置，不等待 AI。
- 必须定义释放、下落、停靠，以及依附窗口关闭、最小化、被遮挡后的行为。
- 必须定义显示层级、透明区域鼠标穿透、角色重叠及桌面边界处理，避免阻碍正常操作。
- 上述身体行为方向已确认，但重力参数、落点选择、碰撞规则和遮挡策略等具体算法仍待设计，不假定统一落回底部等建议已被采纳。

### A0001-R05 动画播放与动作执行

- 播放连续序列帧，最终体验像 GIF，不强制 GIF 格式。透明 PNG 序列、精灵图等仍属候选资产格式。
- 读取帧时长、循环和接触点等最终确认的资产元数据，管理身体与桌面位移协调。
- 按身体状态判断动作是否合法，例如悬挂状态不能无条件切换为失去接触点的双手动作。
- 定义动作优先级、打断、排队和完成语义，处理用户拖拽与正在播放动作的关系。
- 返回接受、拒绝、完成或失败等真实结果，不能将收到指令等同于动作完成。
- 注意循环首尾、动作切换和脚底/手部接触点稳定性；生成质量问题由资产制作验证，运行模块不得假定所有生成帧天然合格。

### A0001-R06 对外事件与清理

- 输出角色位置、可见状态、点击和拖拽事件，供气泡定位和互动入口使用。
- 对外使用显式协议，不泄露原生句柄、框架实例或内部可变状态。
- 请求可关联结果，订阅可取消；移除角色和退出时释放计时器、监听、窗口、资产与采集任务。

## 4. 状态归属与协作接口

唯一拥有的状态：实时位置、依附对象、身体状态、当前动画与播放进度。角色源配置归 B；对话与主动策略归 C；气泡和面板展示状态归 D。

| 输入或输出 | 最小语义 | 协作对象 |
| --- | --- | --- |
| 角色显示资产输入 | 稳定角色标识、包版本、资源与动作描述 | 装配层加载 B 的角色包 |
| 桌面事件输出 | 对象、类型、时间、来源及当前结构 | 经装配交给 C |
| 观察请求与结果 | 范围、暂停/排除约束、关联标识、画面引用或错误 | 经装配与 C 协作 |
| 动作指令与结果 | 角色、动作意图、关联标识、执行状态与失败原因 | 经装配与 C 协作 |
| 位置与用户交互事件 | 角色、坐标、可见性、点击或拖拽 | 经装配交给 D |

正式字段、坐标系、缩放、时间语义、资源路径基准和协议版本应在实现前确定。协议变更同时更新消费者需求与样例，避免各模块各自解释。

## 5. 独立运行和测试要求

提供不依赖其他业务模块、真实模型或网络密钥的独立演示：加载本地样例角色包，在真实桌面或模拟桌面中显示多个角色，通过测试操作入口驱动拖拽和动作。

- 核心规则采用模拟窗口、固定事件、可控时间及样例资产验证。
- 原生窗口、透明区域穿透和真实截图单列为平台集成测试，明确系统与显示环境。
- 覆盖多于两只角色，以验证集合化设计，不将这个测试数量作为产品上限。
- 测试暂停采集、未知动作、坏资产、拖拽打断、窗口消失、过期结果与资源清理。
- 演示与产品使用同一核心实现；后续补齐真实安装、运行和测试命令，不编写虚假通过报告。

## 6. 首版需求验收依据

以下是验收目标。当前已有实现及部分自动验证，尚无全部验收通过结论，各项实际状态以[验证记录](../desktop-world/验证记录.md)为准。

| 场景 | 可观察结果 |
| --- | --- |
| 无 AI 和其他业务模块 | 多角色仍能显示、播放本地动画并接受拖拽 |
| 窗口移动或退出可依附状态 | 位置与身体状态按已明确规则变化，无悬空的失效引用 |
| 执行可用与不可用动作 | 能观察到真实执行或明确拒绝，指令结果可以关联 |
| 受限或暂停观察 | 采集行为遵守范围和暂停要求，不越界采集 |
| 故障角色或坏资产 | 给出可定位错误，其他角色继续正常活动 |
| 透明区域与层级操作 | 用户正常操作不被无关透明区域截获 |
| 移除与退出 | 不残留可见角色、后台监听或未释放任务 |

评价重点是身体反馈及时性、接触关系稳定性、动画连续性、事件准确性、故障隔离与正常桌面操作不受干扰。具体延迟、帧率和资源预算在目标平台实测后确定。

## 7. 未决与暂缓

- 首发系统、显示器数量、DPI/多屏支持、原生宿主与渲染框架。
- 桌面图标和系统元素获取方式及能力差异。
- 身体规则细节、动画格式、接触点与切换协议。
- 截图保留、排除自身界面、敏感区域配置的具体实现。
- 动画生成可行性由 B 验证；复杂双角色拥抱等身体配合不提前纳入确定实现范围。
- 长期记忆、关系系统、新闻回顾和故事引擎不属于本模块。
