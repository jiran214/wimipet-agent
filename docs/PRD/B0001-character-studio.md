## 1. 背景与目标

产品是具有 Meta 感的多角色桌面 AI 陪伴世界。用户决定角色的外貌、性格、说话风格及其如何理解电脑世界；角色通过语言、表情和连续动作与用户及彼此交流。

本模块使用户能够独立制作并维护角色，输出可被最终产品加载的角色包。目标是角色个性与表达能力能被可靠交付，而不只是生成几张好看的图片。当前不讨论商业化，不提前确定完整产品开发排期。

目标效果：用户可以编辑角色与人设，为角色新增动作，预览并选择接受或重做，导出后仍能重新导入；其他模块不需要启动本制作工具就能读取已确认的角色配置与资源。

## 2. 职责与边界

负责角色配置、形象与动作资产导入或生成、生成任务状态、预览调整、校验及角色包导出。文本/视觉对话模型不属于本模块；生图提供方封装在本模块内部，通过可替换接口接入。

不负责共享对话 List、长期记忆、关系演化、故事调度、运行中身体状态、真实桌面控制或群聊界面。制作预览不能依赖桌面运行模块。角色数量不写死为两个，角色配置应相互独立。

## 3. 已确认的产品需求

### 3.1 角色配置与人设自由

- 支持创建和编辑角色身份、名字、人设、头像、形象与动作库引用。
- 不固定角色是否知道自己是 AI，不强制第四面墙台词或统一世界观。
- 用户可配置可爱、幽默、神秘等不同性格；这些是用户选择，不是系统预置的唯一类型。
- 草稿与已确认版本分开管理，编辑不应隐式修改运行中的角色快照。

### 3.2 形象与动作自定义

- 支持导入参考图及已有动作资产，并为调用绘画/生图模型制作形象与动作提供入口。
- 用户可输入动作描述，预览候选，选择采用、修改或重做，加入角色动作库。
- 动作应像 GIF 一样连续播放；这描述体验，不强制 GIF 文件格式。
- 动作应有名称和表达含义，方便互动模块选择；用于播放和身体接触的元数据应能够校验。
- AI 在互动时选择已确认的可用动作，具体选择与执行不属于本模块。

### 3.3 制作与交付闭环

角色配置/参考素材 → 导入或生成动作 → 预览调整 → 用户确认 → 资产校验 → 导出角色包。

生成任务需要明确处理中、成功、失败和取消等状态。用户放弃候选、生成失败或校验失败，不应破坏已确认资产。无需重新生成整个角色即可替换某个动作。

## 4. 暂定序列帧方案与验证约束

暂采用“生图模型生成序列帧，再组合成动画”，后续验证，不锁定模型、工具链或帧资源格式。PNG 序列、精灵图等仅是候选。

以下是验证重点，不代表已解决的能力：

- 角色参考形象、轮廓、比例、配饰和色块跨帧一致；建议后续动作基于同一标准参考形象。
- 简洁 Q 版、扁平卡通和少细节角色适合优先验证，但不强制唯一画风。
- 像素风需关注网格与轮廓稳定；复杂插画关注发丝配饰变化；水彩厚涂关注纹理闪烁；写实与 3D 渲染风关注光照、材质和体积连续性。
- 小幅、短动作和固定视角较易验证；翻滚、转身、复杂遮挡、双角色接触需要额外验证，不能承诺任意动作一次成功。
- 循环首尾需要姿态、速度与方向衔接；不同动作之间也需检查切换。统一待机起止姿态可作为候选策略，并非已定要求。
- 检查透明背景边缘、固定画布尺寸、身体对齐、耳尾手脚裁切、帧时长和播放顺序。
- 接触点应能表达脚底、手、腹部等依附位置。具体数据格式及编辑交互待定。
- 走路等自身动作与桌面位移应分离协调，制作资产需支持运行时避免滑步。

连续帧生成仍可先使用固定素材和假生成响应验证流程；真实视觉效果必须另行验证，不能用流程通过代替生图质量通过。

## 5. 接口与状态归属

本模块唯一拥有角色创作配置、资产草稿及已确认版本。其他模块通过装配层获得只读快照，不直接访问或修改本模块私有存储。

| 输入/输出 | 最小语义 |
| --- | --- |
| 输入 | 用户配置、参考图、动作描述、导入资源、可替换生图提供方 |
| 角色包输出 | 稳定角色标识、包版本、配置/人设、头像与资源引用、动作标识及说明、播放/接触元数据 |
| 任务输出 | 可关联的任务状态、错误、取消结果及待确认候选 |

角色包是交付物，不要求制作工具常驻。装配层显式加载或切换版本；热更新机制尚未确定。密钥不写入角色包或日志。

包版本、路径基准、字段和校验规则需在实现前明确。不得用框架对象、原生句柄或提供方私有响应作为跨模块协议。契约变更需同步消费方及固定样例。

## 6. 独立开发与运行要求

- 不导入其他业务模块实现，不要求其运行，也不读取其私有存储。
- 提供独立制作演示入口，使用本地固定素材及假生图提供方完成整个流程。
- 模块演示与最终产品使用相同核心实现，不另写一套演示专用业务。
- 按需建立源码、演示、测试及样例目录。实现后记录真实安装、运行与测试命令；当前不提供虚假的可执行命令。
- 真实模型验证单独启用并说明环境和结果，默认自动测试不需要账号、网络或真实模型。

## 7. 首版需求的验收方式

以下是后续实现的评价要求，不代表已经通过，也不锁定产品整体发布范围。

1. 独立创建、编辑多个不同人设角色，互不覆盖，并能重新载入配置。
2. 导入样例序列帧，连续预览，确认某动作后导出，再重新导入验证内容一致。
3. 角色包具备明确版本和资源引用；资源缺失、重复动作标识、无效帧或时长可被发现并说明。
4. 假生成提供方可复现成功、失败和取消；未确认候选不覆盖已确认资源。
5. 预览检查透明边缘、裁切、对齐、循环及接触点；自动结构校验与人工视觉检查分别记录。
6. 通过约定角色包样例验证消费者所需信息，不依赖消费者实现才能测试本模块。
7. 退出后任务与资源可释放。真实生成未验证的画风和动作明确标记，不误报可用。
