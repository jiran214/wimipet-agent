# D0001 — 多角色陪伴交互界面首版需求

- 主责模块：D / `companion-ui`
- 日期：2026-11-17
- 状态：首版独立界面及模拟体验台已实现；真实宿主和跨模块协议待联调，人工主观体验待评审
- 关联需求：[A 桌面环境](A0001-desktop-world.md)、[B 角色制作](B0001-character-studio.md)、[C AI 互动](C0001-interaction.md)
- 范围：本模块负责呈现与用户操作，其他模块仅通过契约协作；本文不是完整产品排期或实现承诺。

## 1. 背景与目标

产品是以陪伴为核心的多角色 Meta 桌面世界。角色有用户自定义的人设，能感知真实桌面、与用户及彼此交流，用户作为角色或事件发起者参与故事。故事和关系服务情感寄托，不照搬复杂的小镇经营游戏，不以工作助手或商业化为当前核心。

D 模块让这些互动可见、可参与、可回看。目标是同时保留角色生活在桌面上的陪伴感，以及用户认真交流时的阅读与输入便利。角色数量不限定两只，界面按角色集合工作；不规定每位角色都必须发言。

可观察的目标效果：用户能辨认谁在说话、向谁发送消息、找到错过的交流、分享图片、发起事件；气泡与面板之间切换不丢失上下文，也不产生两份聊天记录。

## 2. 已确认的呈现原则

1. 桌面漫画气泡为主要轻量呈现，可展开对话面板作为深入交流和历史回看的补充。
2. 同一段对话可切换呈现，不把群聊强制绑定角色位置，不要求角色围在一起。
3. 气泡与面板共享 C 提供的消息来源；D 不创建第二份权威消息 List。
4. 面板展开时避免同一句话同时重复占据气泡和面板。桌宠仍可独立播放动作，但动作由 A 负责。
5. AI 决定发言内容和表达意图，气泡布局、文字排版及生命周期由界面程序控制，不用生图模型生成文字气泡。
6. 人设、世界观和语言风格由用户配置；界面不硬编码所有角色都可爱、嘴欠或知道自己是 AI。

## 3. 功能需求

### D0001-F01 多角色身份展示

- 通过名字、头像和稳定角色标识区分角色，支持角色集合更新。
- 展示角色列表和可用交互对象，支持指定角色或面向全体交流。
- 角色增减不应导致其他角色消息被误归属；历史角色如何显示的具体策略待定。

### D0001-F02 桌面气泡

- 根据 A 提供的角色位置与显示状态放置气泡，无须自行计算身体运动。
- 适合日常短句与角色接话；避免多个长气泡同时遮挡桌面，让用户追着不同位置阅读。
- 保留发言身份与顺序，允许用户通过面板回看已消失的内容。
- 气泡时长、最大同时展示数、越界避让和未读提示形式属于待细化交互，不能在本需求中假定固定数值。

### D0001-F03 可展开对话面板

- 按头像、名字和消息顺序展示交流，提供输入与回看入口。
- 用户可在轻量陪伴和深入交流之间切换，不因打开或关闭面板创建新会话。
- 使用 C 提供的获准展示视图，不自行推断私聊可见性，不因隐藏面板而改变消息权限。
- 面板不必常驻；具体窗口、浮层或其他容器形式待视觉与平台选型确定。

### D0001-F04 用户主动输入

- 接收文字、图片拖入与明确接收对象，将操作转为结构化请求提交给 C。
- 提供可辨识的输入、提交、处理中和失败状态，避免无反馈等待或误认为发送成功。
- 图片理解由 C 完成；D 负责输入和附件展示。其他文件类型支持范围尚未确认。
- 不固定“每人轮流回答一次”，发言调度由 C 决定。

### D0001-F05 故事参与和导演入口

- 用户可以加入角色交流，也可以通过入口提交突发事件或事件条件，作为导演参与故事。
- 事件输入与普通聊天在语义上应可区分，交由 C 解释和推进；D 不生成剧情或控制关系变化。
- 神秘盒子、新访客等只是事件例子，不构成必须实现的事件模板列表。
- 事件编辑形式、是否告知角色由用户安排、新闻回顾等尚未确定；新闻不是首版必选功能。

### D0001-F06 设置与角色制作入口

- 提供观察暂停和相关设置操作入口，显示上游实际状态；不能只切换一个本地按钮而不提交请求。
- 提供打开或嵌入 B 制作工具的入口，不重复实现人设编辑、序列帧生成和资产校验流程。
- 观察范围与频率由 C 管理，采集约束由 A 执行，D 负责表达设置意图与显示结果。

## 4. 职责边界与状态归属

D 唯一拥有面板开合、输入草稿、滚动位置、布局和气泡展示状态。角色源配置归 B，身体和播放状态归 A，对话 List、上下文筛选、轮次及模型任务归 C。

D 不调用模型、不操作系统截图、不播放序列帧、不判定动作合法性、不维护长期记忆、不直接读写其他模块私有状态。原生窗口和坐标适配通过宿主接口注入。

业务模块不得导入其他业务模块实现。生产环境由 `apps/desktop` 连接公开接口；独立演示注入固定数据和回调替身。D 的界面状态不能被装配层变成第二套业务状态。

## 5. 输入输出契约

| 方向 | 最小语义 | 责任 |
| --- | --- | --- |
| 输入角色摘要 | 稳定身份、名字、头像引用、可交互状态 | 消费快照，不修改 B 源配置 |
| 输入消息视图 | 消息身份、发言者、有序内容、获准展示范围 | C 先过滤；D 只呈现 |
| 输入位置与交互事件 | 角色标识、位置、坐标约定、可见状态、点击等 | A 提供事实；D 管理气泡布局 |
| 输入处理及设置状态 | 请求关联、等待/失败/完成、观察状态 | 以实际结果更新界面 |
| 输出用户请求 | 接收对象、文字或附件引用、输入类型 | 交由 C 处理 |
| 输出事件与设置意图 | 事件条件、设置变更、请求关联 | 不在 D 执行模型或采集逻辑 |
| 输出制作入口请求 | 打开制作工具的意图 | 装配层连接 B |

消息、坐标、附件和错误的正式字段后续约定；跨模块请求需要关联标识，避免迟到结果覆盖新操作。无需向 D 泄露模型提供方私有响应、原生句柄或整个未过滤 List。

## 6. 独立演示与测试要求

提供可独立启动的界面演示，使用假角色、假位置、固定消息流和可观察操作回调。不需要真实模型、系统截图、桌面模块或角色制作工具在线运行。演示与正式产品共用核心界面逻辑。

### 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 超过两只角色在不同位置交替发言 | 身份清楚、顺序一致，不要求角色聚拢 |
| 从气泡打开面板再关闭 | 同一会话与消息标识，无重复记录；错过的内容可回看 |
| 指定角色和全体发送 | 回调携带正确接收对象；不把指定消息改为广播 |
| 注入不包含私聊内容的获准视图 | UI 不补取或泄露完整 List |
| 拖入图片、提交事件 | 输出正确请求类型，展示受理或失败反馈 |
| 操作暂停观察 | 发出设置意图并按返回状态更新，而非仅本地假成功 |
| 长消息、屏幕边缘、位置更新 | 内容仍可阅读和回看，布局不依赖身体实现 |
| 角色移除、空列表、输入失败 | 状态明确，不误用旧角色身份，不静默丢失草稿 |
| 打开制作入口 | 请求可被替身捕获，无需 B 真正启动即可验证 |
| 停止演示 | 解除订阅和计时器，不残留后台更新 |

当前 D 实现使用原生 JavaScript 与模块内 Node.js 启动器，自动测试默认不需要密钥、账号或真实个人截图。启动方式、固定样例步骤和分层验证记录见 [使用与验收](../companion-ui/使用与验收.md)，实际本地接口见 [接口草案](../companion-ui/接口草案.md)。核心和浏览器检查已记录；不能将独立模拟检查等同于真实宿主集成验收。

本地体验策略（实施选择，尚非永久确认需求）：字母占位头像、纸张/苔绿视觉、三个短气泡上限、十秒生命周期、图片最多四张且每张 5MB、窄屏上下布局。后续根据真人体验与宿主约束调整；没有扩展暂缓功能。

## 7. 待定、暂缓与关联约束

- 待定：界面画风、布局尺寸、气泡寿命、拥挤处理、面板宿主、快捷入口、多屏缩放坐标、附件错误提示细节。
- 待定：首发平台和框架、具体性能预算、角色数量上限、设置持久化。
- 暂缓：复杂长期记忆、关系可视化系统、新闻日报、离线故事推进、完整剧情编辑器。
- 与 A 协调位置与宿主契约，与 B 协调制作入口及角色摘要，与 C 协调消息视图和用户意图；跨模块需求分别编号并引用，不扩张 D 职责。
