# A 模块接口与身体规则（实现验证版）

主责：desktop-world。版本 0.1.0，2026-11-17。以下为 A 内部原型协议与算法选择，服务于可运行体验；**尚未与 B / C / D 协商，不声称跨模块兼容，不将算法选择升级为产品确认需求**。其他模块需求文件未修改。正式接入前由装配层适配或协商版本。

## 导入与依赖注入

源码位于 `modules/desktop-world/src/desktop_world/`，只依赖 Python 标准库。`World` 是身体与播放状态唯一拥有者，不调用 Tk、系统窗口、模型或其他业务模块。`Playground` 是本模块的演示宿主；`WindowsDesktop` 为平台适配器。将结构输入 World，再由宿主读取其状态绘制。截图采集器经 `CaptureGate.capture(..., backend)` 注入，核心不会自行枚举或截图。

公开使用 `World`、`Package.load`、`Rect`、`Surface` 和 `CaptureGate`。`Pet` 等是模块内部可变状态；外部消费者使用 `snapshot()` 或订阅事件，不修改 `world.pets`。未来进程间传输需要 JSON 外观层，当前不是 HTTP 服务或已承诺的 RPC。

## 只读角色包：A-display/1

清单路径是资源基准，资源必须解析到同目录或子目录，拒绝 `..` 越界及符号链接越界。支持最高 512×512 的透明 PNG 序列；不支持 GIF、精灵图、骨骼动画。实际图片由 Tk 在载入阶段解码；不能解码则整只角色失败，其他实例不受影响。

```json
{
  "schema": "A-display/1",
  "id": "sample-moss",
  "version": "1.0.0",
  "name": "苔苔",
  "actions": {
    "idle": {
      "loop": true,
      "priority": 0,
      "states": ["standing", "lying", "clinging", "hanging", "falling", "dragging"],
      "contactKind": "feet",
      "frames": [{"file": "idle-0.png", "durationMs": 220, "contact": [32, 60]}]
    }
  }
}
```

该例为最小清单；依附体验还需要对应姿态的动作，完整样例在模块自带 `fixtures/moss/character.json`。`id` 标识角色包；`World.add` 的 `pet_id` 标识实例，两者分离，可从同一包创建任意数量实例，没有硬编码双角色上限。`version` 必须显式提供，不热更新、不回写、不持久保存位置。资产是项目自绘的固定公共样例，生成源 `fixtures/build_samples.py` 可重建，不依赖其他模块。

帧时长 10–10000 毫秒；接触点位于帧局部像素坐标，允许位于宽/高边界。渲染原点 = 世界接触点 − 当前帧接触点。不同帧可以有不同局部接触点，世界接触点保持不变。`contactKind` 为 `feet`、`body`、`top-grip`、`side-grip`。挂、贴、趴需要相符接触类型，不能用普通 idle 假装保持悬挂；idle 是空闲/转换回退帧，不会作为不合法指令被接受。

## 坐标、时间与来源

模拟场为左上原点、X 向右、Y 向下的像素坐标，工作区 `(0,0,900,600)`。Windows 模式启用每显示器 DPI 感知，坐标为虚拟桌面物理像素，可有负数；当前身体可活动范围取主屏工作区。窗口采用 GetWindowRect 外框，宽高不含右下边界。跨模块的逻辑像素 / CSS 像素缩放尚未约定。

`timeMs` 是 World 创建后由 tick 累加的单调场景时间，不是 UTC。宿主使用 `time.monotonic()` 驱动，单次 GUI 延迟最多推进 250ms，暂停主线程不会瞬移补齐全部动画；测试可显式推进固定时间。`sequence` 是单个 World 内递增事件序号。恢复场景会创建新 World，序号及时间归零，消费方需结束旧订阅。截图策略 `epoch` 与 World 时间分离。

事件最小外壳：`protocol: A-world/1`、`sequence`、`timeMs`、`source: simulation|windows`、`type`，再附类型对应字段。结构事件带 `surfaceId`、`rect`、`minimized`、`occluded`、`active`、`observedAtMs` 和 `objectSource`。原生对象 ID 为本次适配器生命周期内的 opaque ID；原生句柄不输出。窗口来源区分自带模拟与真实 Windows，不提供虚构图标信息。轮询可能漏掉 100ms 内的短暂变化，也不能完全解决句柄在两轮之间被重用的问题。

## 身体规则

这些具体规则可在平台体验后修订，不代表已确认的最终物理设计：

| 状态 / 操作 | 本次实现 |
| --- | --- |
| standing | 脚接触工作区底边，默认 idle |
| falling | 重力 1000px/s²，无横向速度，16ms 最大物理子步，落到底边后 standing |
| dragging | 最高优先级，立即中止当前及排队动作，解除依附，保持按下点相对身体偏移 |
| lying / hanging | 接触世界坐标为目标窗口顶边 + 水平偏移；分别使用 body / top-grip 动作 |
| clinging | side-grip 接触窗口右侧，Y 为窗口顶边 + min(64, 高/2) |
| 窗口移动 / 缩放 | 不等待模型，更新接触点；水平偏移最多为缩窄后的窗口宽度 |
| 窗口最小化 / 关闭 | 中止依附动作，清除目标引用，夹回工作区后下落；恢复不自动重新依附 |
| 窗口被完全遮挡 | 保持依附并继续动画，但隐藏角色；解除遮挡后显示 |
| 窗口移出工作区 | 保持真实接触点，不把角色与窗口拆开；完全离开工作区则隐藏 |
| 边界 / 重叠 | 非依附身体夹在工作区，角色间不碰撞；后添加的实例绘制/创建在上，重叠处优先接收点击 |

原生角色是常驻顶层工具窗口，设置 NOACTIVATE；有效角色像素会占用鼠标命中区域，透明区域通过 HRGN 排除。不尝试覆盖安全桌面或保证覆盖独占全屏。原生遮挡算法只处理单个更高窗口完整包含目标窗口；多窗组合遮挡、部分遮挡、无标题覆盖层和本模块控制面板遮挡不精确处理，自身控制 UI 不作为可依附环境输出。

## 动作与执行结果

`command(pet_id, action, request_id, enqueue=False)` 由调用方提供当前 World 内唯一的请求标识。核心按动作存在性、身体状态、接触类型、优先级和队列容量返回结果；目前不提供跨会话幂等去重或持久化。

- `accepted` 表示已开始播放，`queued` 表示尚未开始，均不等于完成。
- `completed` 只在有限动作最后一帧时长结束后输出；循环动作必须显式打断，不自行完成。
- `rejected` 表示未知动作、不合法身体状态、接触类型不符、低优先级或队列已满。
- `interrupted` 表示被新动作、拖拽、依附切换、窗口失效、移除或退出中止。相同/更高优先级新动作可抢占；抢占会取消旧队列，较低优先级明确拒绝。
- `failed` 由宿主通过 `fail_action(pet_id, request_id, reason)` 报告实际播放故障；只接受当前请求，旧请求故障不会影响新动作，失败后取消队列并回退。宿主渲染器集成时应调用该接口，不把播放失败冒充完成。
- 队列最多 8 条，在前动作完成后重新验证身体状态；不保证排队即能执行。核心播放使用已校验的本地帧，不涉及模型请求，宿主加载/采集故障以明确异常或面板错误报告，不伪造 completed。

`action-result` 携带 `petId`、`requestId`、`status`、`reason`。移除实例会先终结其未完成请求。`subscribe(callback)` 返回可重复调用的取消函数，给消费者深拷贝，消费者异常不阻断核心。交互与位置事件包括 `click`、`drag-start`、`drag-end`、`position`、`added`、`removed`、`attached`、`released`、`docked`。快照包含角色、接触点、身体状态、可见性、依附、动作、帧序号，不包含对话记录。

## 受控截图

`CaptureGate(allowed)` 接受授权矩形；`configure(allowed=..., excluded=..., paused=...)` 每次增加 epoch。`capture(request_id, rect, backend)` 在调用 backend 前检查：整数正尺寸、授权范围内、最多 3840×2160 像素、未暂停、不与任何排除矩形相交。相交时拒绝整次采集，不先采集敏感区域再涂黑。请求失败会回收 pending 项。

异步适配者可用 `begin/finish`：Ticket 固化 requestId/epoch/rect。采集中策略变化，即使暂停后又恢复，旧结果仍标 `stale` 且丢弃 image。当前 Tk 宿主同步执行截图；慢截图会暂时阻塞 UI，此限制尚未做性能验收。无需在系统窗口事件发生时截图。

原生 backend 截图前隐藏已知的本模块窗口、DwmFlush，finally 恢复；像素只保留内存预览。角色另尝试设置 WDA_EXCLUDEFROMCAPTURE，失败不作为安全保障，自身排除依赖隐藏流程。Microsoft 文档明确该 API 不能作为严格内容保护保证：[SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。GDI 位图先解除选择再读取，HRGN 成功设置后交系统管理，依据 [GetDIBits](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-getdibits) 与 [SetWindowRgn](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowrgn)。

没有默认落盘、保留周期、自动个人截图反馈或语义识别。未来其他进程的气泡 / 面板排除、异步采集取消、画面引用的生命周期协议需单独协商。

## 清理与待联调

`World.dispose()` 中止未完成动作并释放角色、结构、订阅，重复调用安全；随后禁止变更。`CaptureGate.dispose()` 清空请求并禁止采集。宿主退出时取消 Tk after、回放和图像引用，销毁所有自有窗口；Win32 轮询没有系统事件钩子或常驻后台线程，临时 GDI 对象在 finally 释放。
