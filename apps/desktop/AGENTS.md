# 产品装配层协作规则

## 人工联调与渐进体验

- 不等四个模块全部完成再首次装配；最小公开契约可用时，提供可启动的部分集成入口，缺失模块使用明确标记的替身。
- B → A：人工将制作台导出的角色包加载到桌面，检查形象、动作、循环与接触点是否一致。
- C → D：人工输入文字、图片和故事事件，检查真实消息能否在气泡与面板中正确呈现、回看及切换。
- C → A：检查动作意图能执行或明确拒绝，执行结果能返回 C；不把收到指令当作动作完成。
- A → D：检查角色移动时气泡跟随，以及真实桌面上的层级、缩放和遮挡效果。
- 完整链路就绪后体验多角色交流、用户插话、观察暂停与恢复、模型失败时的身体响应及退出清理。
- 提供简明启动步骤、固定样例、当前真实/模拟模块清单和已知限制；允许恢复测试场景，并记录模块版本及问题复现步骤。
- 独立体验与集成体验分别记录结论；不把部分链路成功宣称为成品已经完成。

遵循根目录 `AGENTS.md` 及四模块需求：[A 桌面](../../docs/PRD/A0001-desktop-world.md)、[B 制作](../../docs/PRD/B0001-character-studio.md)、[C 互动](../../docs/PRD/C0001-interaction.md)、[D 界面](../../docs/PRD/D0001-companion-ui.md)。

## 目标与效果评价

- 将四个独立模块装配成一致的陪伴产品，保持各模块的职责和唯一状态归属。
- 以角色包可加载、用户输入到回复及动作反馈可贯通、观察暂停有效、退出资源可释放作为未来集成效果评价。
- 装配层不新增第五条业务需求编号；业务变更归入 A/B/C/D 主责模块，跨模块变更拆分并互相引用。装配专属配置和生命周期约定记录在本文件，新增独立编号体系需另行确认。

## 当前阶段

已提供 v0.1.0：`python apps/desktop/server.py --offline` 启动 A/C/D 网页舞台并启动 B 制作台；不带 --offline 使用 OpenAI SDK Chat Completions。运行与限制见根 README，验证见 `docs/releases/v0.1.0.md`。

## 首轮复盘后的装配约束

- 根 AGENTS.md 的 wimipet/1 是唯一跨模块基线；四模块已迁移并合并，装配验证范围需持续记录。接入前记录各模块版本、能力差异和适配结果，不能只将协议标识改为 v1。
- 每轮明确装配负责人并先选择原生宿主、IPC/线程模型、资源桥和关闭顺序；避免模块各自完成却无人负责组合入口。
- 优先实现 B→A 角色包、C→D 消息及 C→A→C 动作的最小真实链路，再扩到附件、观察设置和位置。每条链路都验证拒绝、取消、失败和重置后的迟到结果。
- 允许无损字段映射、资源解析、单位与坐标换算；禁止猜测身体接触语义、补假用户台词、吞掉多余图片、虚报完成或复制第二个权威 List。缺失能力回到主责模块修复。
- 以 instanceId 映射同包多实例；显式区分 epoch 时间、单调时间、物理像素与 CSS 像素，处理负坐标和显示器缩放。
- D 的消息订阅必须连接 C 获准视图；调试管理员数据不进入角色可见流，演示 host 不进入正式权威消息链。
- 统一注册 A/D 自有宿主的截图排除，设置暂停须等 A 实际确认；不能只有 D 本地开关。跨进程资源引用由资源桥管理，退出按依赖逆序释放。
- 当前探针的 feet-only/全状态假设只证明样例可转换，禁止作为生产转换默认值。
- 集成验证使用共同固定样例、临时端口和可追踪实例，仅停止自己启动的进程；记录部分成功和未验证项，不把四个演示同时运行视为装配完成。

## 职责

- 创建四个业务模块的实例，注入配置、模型提供方、宿主能力和其他显式接口。
- 加载经过校验的角色包，把角色配置、动作描述和显示资产分别传给需要它们的模块。
- 连接用户输入、消息视图、桌面事件、观察请求、动作指令与执行结果。
- 协调启动、退出、角色加载/移除、任务取消和资源清理。
- 负责最终产品入口、配置加载、集成诊断及打包发布。

## 边界与依赖

- 可以依赖四个模块的公开入口，不访问其私有实现或存储。
- 不实现人设决策、上下文筛选、主动观察策略、身体规则、动画生成或气泡布局。
- 不维护另一份权威消息 List 或身体状态，不使用隐式全局总线掩盖接口。
- 平台宿主和界面嵌入的连接可以放在此处；具体业务仍归对应模块。
- 角色制作通过工具入口和角色包衔接，不要求日常陪伴时持续运行生成工具。
- 当前采用 Python 单 asyncio 所有者线程 + 本地 HTTP + B Node 子进程 + 浏览器 D；原生透明宿主仍待后续整合。

## 独立运行与集成验证要求

- 允许使用模块替身装配最小宿主，检查配置、连接和生命周期，无需真实 AI。
- 逐步替换为真实模块验证同一组契约；不为测试另写一套业务流程。
- 验证角色包加载、多于两只角色的输入输出路由、消息到动作链路及执行反馈。
- 验证用户消息可见范围在界面中不泄露，气泡/面板共用消息来源。
- 验证暂停观察生效、模型失败不阻塞身体交互、迟到结果和模块退出可清理。
- 验证缺失或损坏角色包、模块初始化失败、退出期间存在任务等场景。
- 真实原生桌面和模型测试需说明环境；未执行的检查应明确标注，不宣称通过。
