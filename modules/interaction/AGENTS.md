# interaction 模块协作规则

## 人工体验入口：互动实验室

- 除自动化或命令行入口外，提供简单可操作的测试页面，允许配置参与角色、人设和模拟事件，显示交流内容、动作意图及处理状态。
- 自带多个不同人设、固定图片、模拟桌面截图和固定回复；不依赖真实桌面、D 的正式界面或其他模块。
- 用户可对全体或指定角色说话、分享图片、注入故事事件，在自动交流中插话或停止，暂停观察。
- 在仅用于调试的查看区显示选中角色实际收到的上下文，便于人工检查私聊隔离；该调试权限不进入正式角色可见视图。
- 固定响应模式验证流程；接入真实文本/视觉模型后，人工评价角色差异、语境理解、接话自然度、陪伴感和节奏，不能以前者代替后者。
- 提供明确的模式标识、恢复样例会话、重复输入事件和保存必要诊断信息的能力；重置不暗示已经实现长期记忆管理。
- 测试页面属于本模块调试工具，不承担 D 的正式气泡、聊天面板或视觉设计职责。

本目录负责 AI 理解、对话和互动决策。遵循根目录 `AGENTS.md` 和 [C0001 首版需求](../../docs/PRD/C0001-interaction.md)。

## 模块目标

让多个角色依据各自人设与可见上下文理解用户和桌面，形成有差异、可延续的陪伴交流与故事；同时使主动行为有节制、调度可停止、失败可恢复。

- 以语境关联、角色差异、消息范围正确、自然接话及用户可打断作为效果评价重点。
- 固定响应测试验证机制，真实模型场景评审验证陪伴表达；不得混淆两者。
- 用户决定人设与 Meta 世界观，不固化角色性格；复杂长期记忆和关系系统暂缓。

## 需求编号与聚焦

- 本模块需求使用 `docs/PRD/CNNNN-主题.md`，从 `C0001` 独立递增，与 A、B、D 编号无关。
- 每次需求聚焦本模块；修订同一需求更新原文，新增独立需求取 C 序列最大编号加一，不复用删除编号。
- 跨模块只约定公开接口、输入输出和验收衔接；相关实现分别归属各模块需求并互相引用。

## 当前阶段

仅有设计与协作规则，尚无实现、可执行入口和测试命令。下列要求约束后续实现，不代表当前能力已经完成；不要提前锁定语言、框架、模型提供方或进程结构。

## 职责

- 接收用户文字、图片、桌面事件及用户注入的故事事件。
- 控制主动观察与互动节奏、暂停、观察范围及过期结果处理，通过接口按需请求画面。
- 结合视觉理解、人设和共享消息 List 产生回复及动作意图。
- 按角色筛选上下文，组织私聊、群聊、接话、用户插话和自动交流停止。
- 在模块内封装文本与视觉模型接入，管理取消、超时和失败。

## 边界

- 不直接调用操作系统截图，不渲染窗口或动画，不决定具体物理位置。
- 不管理角色源配置和资产生成，加载角色配置快照及可用动作描述。
- 只使用共享消息 List 与可见性筛选；不提前建设长期记忆、关系数据库或独立故事引擎。
- 输出动作意图不等于执行成功，应消费执行反馈；不可假定角色完成了被拒绝的动作。

## 接口与状态归属

输入：角色配置与动作描述、用户输入、环境事件、按需画面、动作执行结果。
输出：对话更新、动作意图、观察请求、处理状态。
唯一拥有：共享消息 List、角色上下文筛选、对话轮次、主动互动策略和模型任务状态。
视觉/文本提供方、画面采集和时钟均通过可替换接口接入。

- 不导入其他业务模块实现，不读取其私有目录、数据库或可变状态。
- 对外只暴露明确的公开接口和数据；依赖通过装配层注入，独立运行时使用本地替身。
- 公开协议变更需同步更新本模块需求、相关模块契约与样例，并说明兼容性；避免泄露框架对象或原生句柄。
- 具体字段与方法签名在实现前单独约定，本文件只确定语义边界。

## 独立运行与测试要求

- 使用命令行或最小测试入口加载多个角色，输入文字、图片与模拟事件，输出消息和动作意图。
- 默认使用固定模型响应、假画面采集和可控时钟，不要求真实桌面或网络密钥。
- 验证消息顺序与可见范围、指定角色消息隔离、多角色差异、自动交流停止、用户插话。
- 覆盖超时、取消、迟到结果、单角色失败、观察暂停及动作拒绝；不让模型等待阻塞整个会话。
- 角色数使用集合处理，测试包含多于两只角色，不硬编码双角色逻辑。

## 后续实现组织

- 按需建立 `src/`、`demo/`、`tests/`、`fixtures/`；当前不创建空实现或占位测试。
- 实现后记录确切的安装、演示、测试命令和环境前提；演示与产品必须使用相同的核心实现。
- 提供清晰的启动、停止与资源清理方式；后台任务、订阅、文件资源应可释放。
- 自动测试默认不使用真实账号、个人桌面截图或外部模型；真实集成验证显式启用。
