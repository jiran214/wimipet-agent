# character-studio 模块协作规则

## 人工体验入口：角色制作台

- 提供可直接操作的独立制作界面及样例参考图、序列帧，不要求先启动 A/C/D。
- 首先让用户完成“创建角色和人设 → 导入样例动作 → 连续预览 → 调整 → 确认 → 导出 → 重新导入”，无需手工整理资源文件。
- 真实生图接通后，另行体验“输入动作描述 → 生成候选 → 预览 → 接受或重做”，并尝试取消和失败恢复。
- 清楚标注固定素材、假生成与真实生成；样例流程成功不能证明真实生成质量。
- 人工检查人设编辑是否自由、操作是否易懂、跨帧形象是否稳定、循环与切换是否突兀，以及导出再导入是否完整。
- 提供恢复样例项目与重复预览；保护已确认资产，重置不得静默覆盖用户项目。记录素材版本、生成模式、问题帧和错误信息。

本目录负责角色与动作资产制作。遵循根目录 `AGENTS.md` 和 [B0001 首版需求](../../docs/PRD/B0001-character-studio.md)。

## 模块目标

让用户不依赖其他业务模块即可创建属于自己的角色、人设与连续动作，经过预览确认后输出稳定、可校验的角色包，让角色差异与表达能力能够可靠进入最终陪伴产品。

- 以“编辑配置 → 导入或生成 → 预览确认 → 校验导出 → 重新导入”闭环评价效果。
- 以人设自由、跨帧角色一致性、资产完整性和失败不损坏已确认版本评价质量，不以生成图片数量代替可用性。
- 不将待验证的生图能力承诺为任意画风、任意动作的一次成功。

## 需求编号与任务范围

- 本模块使用独立的 B 序列，文件格式为 `B0001-简短主题.md`，存放于 `docs/PRD/`。
- 新需求仅按 B 序列最大编号递增，与 A、C、D 序列互不影响；不复用已使用编号。
- 每次需求聚焦角色制作模块；跨模块部分只描述输入输出契约，其他模块的业务变更应分别建立对应需求并互相引用。

## 当前阶段

仅有设计与协作规则，尚无实现、可执行入口和测试命令。下列要求约束后续实现，不代表当前能力已经完成；不要提前锁定语言、框架、模型提供方或进程结构。

## 职责

- 创建、编辑角色身份、名字、人设、头像与形象配置。
- 导入或生成角色形象和序列帧动作，管理生成任务及失败重试、取消。
- 预览、调整和校验动作资源，维护动作说明与必要的播放、接触点元数据。
- 导出可供其他模块离线读取的角色包。

## 边界

- 不管理对话 List、长期记忆、运行中身体状态或真实桌面控制。
- 不依赖桌面模块运行预览；可以使用本地轻量预览工具。
- 序列帧生成仍待验证，不承诺任意画风或动作一次生成成功。
- 生图接入封装在本模块内部；不引入强制共享模型服务。

## 接口与状态归属

输入：用户角色配置、参考图、动作描述、导入资产和生图提供方接口。
输出：版本明确、经过校验的角色包，以及制作任务状态。
唯一拥有：角色创作配置、资产草稿与已确认版本；运行模块加载只读快照。
角色包更新通过显式重新加载或版本切换生效，具体热更新机制尚未确定。

- 不导入其他业务模块实现，不读取其私有目录、数据库或可变状态。
- 对外只暴露明确的公开接口和数据；依赖通过装配层注入，独立运行时使用本地替身。
- 公开协议变更需同步更新本模块 PRD、受影响模块的契约说明与相关样例，并说明兼容性；避免泄露框架对象或原生句柄。
- 具体字段与方法签名在实现前单独约定，本文件只确定语义边界。

## 独立运行与测试要求

- 无需其他业务模块即可编辑角色、导入样例序列帧、预览和导出。
- 默认可用固定素材与假生图提供方完成演示；真实生图测试单独启用。
- 验证资源引用完整性、帧尺寸与时长、动作标识唯一性、包版本及往返导入导出。
- 覆盖生成失败、取消、无效帧和用户放弃确认；失败不破坏已确认资产。

## 后续实现组织

- 按需建立 `src/`、`demo/`、`tests/`、`fixtures/`；当前不创建空实现或占位测试。
- 实现后记录确切的安装、演示、测试命令和环境前提；演示与产品必须使用相同的核心实现。
- 提供清晰的启动、停止与资源清理方式；后台任务、订阅、文件资源应可释放。
- 自动测试默认不使用真实账号、个人桌面截图或外部模型；真实集成验证显式启用。
